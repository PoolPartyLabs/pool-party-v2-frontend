# Cash+ local operator

These commands execute a local Arbitrum fork through official Aqua, SwapVM and Aave contracts. They do not start an API, hold private keys, or send live-chain transactions. Investor browser code imports no operator module. Every write requires a loopback HTTP RPC, chain ID 31337, Anvil fork metadata and a source block hash verified against Arbitrum 42161. The saved Anvil instance ID rejects a silent reset.

The contract workspace defaults to `../cash-plus-contracts/contracts`; set `CASH_PLUS_CONTRACTS_ROOT` if needed. Build with `FOUNDRY_PROFILE=cashplus`. It is essential to respect both EIP-170 runtime size and EIP-3860 init-code size; the deployment script checks both before sending. Current contracts are close to the runtime limit and must not be built with Active Reserve's default optimizer profile.

## Start or connect to a fork

```sh
anvil --host 127.0.0.1 --port 8550 --chain-id 31337 --fork-url https://arb1.arbitrum.io/rpc --silent
pnpm cash-plus:deploy-fork --rpc http://127.0.0.1:8550
pnpm cash-plus:verify
```

Anvil `--silent` avoids printing even its public test private keys. The CLI uses unlocked test accounts from `eth_accounts` and creates distinct governance (0), investor (1), keeper (2), guardian (3) and counterparty (4) roles. Fixture funding impersonates the two Aave reserve holders only on this local fork. It temporarily funds their gas, transfers fixture underlying, and immediately stops impersonation. No token balance/storage patch is required. This funding is a test fixture, not real revenue or customer volume.

Public RPC historical state can expire. The September 13 rehearsal's original source block stopped serving fresh storage/account requests while a new latest fork succeeded. An archival RPC or a fresh explicitly created fork/run is needed in that case. These scripts never reset an existing chain. `deploy-fork` reuses/verifies an existing saved deployment by default; `--new-run` deliberately creates another vault and manifest on the selected fork. Preserve the prior evidence and reconcile pending investor transactions first.

The deployment factory creates and seeds atomically. Sponsor seed is 1,000 USDC; a disclosed sponsor donation of 100 USD₮0 supplies the secondary inventory before investor entry. The initial secondary inventory is parked entirely in its actual Aave reserve, making the subsequent USD₮0 output prove JIT withdrawal. USDC hot target is 5% of NAV. Contract fees are zero. Stablecoin prices, interest, balances and output amounts are actual fork reads; USD₮0 is the current representation at the selected Arbitrum token address.

The browser manifest is `src/lib/cash-plus/config/deployment.generated.json`. ABI files are generated by `pnpm cash-plus:export` and formatted with Biome. The manifest contains public addresses, local RPC, source block, deployment hash and bytecode hashes. Operator state, roles, ABI hashes, fixture policy and pending journal live in ignored `scripts/cash-plus/.local/`.

## Operate and rehearse

```sh
pnpm cash-plus:demo --step status
pnpm cash-plus:demo --step invest --amount 1000
pnpm cash-plus:keeper --once
pnpm cash-plus:counterparty --scenario normal --amount 10
pnpm cash-plus:counterparty --scenario exceeds-limit
pnpm cash-plus:demo --step withdraw
pnpm cash-plus:demo --step capacity --cap 1500
```

Use the browser for investor approval/deposit/redemption when presenting the UI. The CLI investor commands are separate reproducible test actors, and the full non-browser rehearsal is `pnpm cash-plus:demo --step rehearse`. The designated investor remains fully exited after that rehearsal, with lifetime cashflows retained.

For a persistent serial loop, run `pnpm cash-plus:keeper`; it checks health, parks excess, restores configured buffers, reconciles/rotates canonical orders and waits ten seconds. `--iterations 2` is a bounded rehearsal. A failure stops the loop instead of retrying an unknown write. Each signer is locked across simulation, submission and receipt. A crashed process's lock is recovered only after proving its PID is absent. Existing pending hashes are resolved before any new send; timeout or an unresolved/reverted receipt stops the command and retains its journal. Inspect the saved receipt and reconcile the state explicitly before restarting after a reverted transaction. Receipt/state writes are atomic, and evidence/order entries merge across independent signer processes.

Each canonical ship is independently encoded in TypeScript and compared byte-for-byte with the onchain factory; router order hashing is also checked. All four maker hooks use empty data. Counterparty calldata fixes exact input, input-first settlement, transferFrom+Aqua.push, no callbacks, default recipient equal to counterparty, minimum output and a 60-second deadline. Output-first and exact-output cases are covered in contracts. Virtual amounts are based on actual current underlying/receipt balances, including Aave's one-unit rounding.

`exceeds-limit` must decode the actual `FillLimit` custom error. It does not count a transport error, stale order, failed allowance or any other revert as a successful risk demonstration. The capacity command submits the explicit `SIMULATED_CAPACITY_REPORT_CASHPLUS_DEMO_V1` reason hash; describe it as a simulated capacity decision.

## Evidence and verification

```sh
pnpm exec tsx scripts/cash-plus/snapshot-history.ts
pnpm exec vitest run tests/cash-plus/cli.test.ts
```

`.local/evidence.json` includes manifest, roles, ABI hashes, policy fixture, pending state, all successful operation hashes/custom events, current NAV/components and investor cashflows. `.local/<txhash>.json` retains full receipts, including ERC-20 and official Aqua/SwapVM logs. `.local/snapshot-history.json` reads before/after investor and conversion values at the actual receipt block and records block hashes. `.local/rejected-limit.txt` holds the exact expected rejection. Keep the contract test logs with this bundle. These local receipts have no valid public explorer links.

Meaningful CLI tests cover official opcode/argument packing, complete-order hashing, malformed parameter rejection, taker flags and minimum/deadline widths, local-only RPC restrictions, concurrent signer locks, stale process recovery and pending receipt success/revert/timeout behavior. Contract tests separately execute real deployed protocols; a compiler or mock-router test alone is insufficient.

The demo does not infer annual returns or commercial demand from its own fills. Small positive conversion margin on this fork is evidence of accounting and execution, not production profitability or an audit.
