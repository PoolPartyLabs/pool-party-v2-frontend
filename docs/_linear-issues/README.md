# Linear, Initial Issues

List of issues to create in Linear before development starts. Organized by epic.

## Execution order

1. **BOOTSTRAP-001** (once): runs `figma-inventory` to generate all feature issues.
2. **FOUNDATION** (sequential): repo setup, tooling, configuration.
3. **DESIGN_SYSTEM** (sequential): tokens first, then primitives. Blocks features.
4. **MOCKS_AND_I18N** (parallel to Design System): mock and translation foundation.
5. **FEATURES** (generated by BOOTSTRAP): implemented after Foundation and DS.

## Files

- `BOOTSTRAP.md`, single issue that triggers the Figma inventory.
- `FOUNDATION.md`, setup issues (13 issues).
- `DESIGN_SYSTEM.md`, design system issues (15 issues).
- `MOCKS_AND_I18N.md`, mock and i18n foundation issues (5 issues).

## How to use

Each issue is formatted as a spec. **Status (2026-05-30):** Foundation is live in Linear as **POO-47..59** (13 setup) + **POO-60..79** (tokens, mocks/i18n, 12 primitives, AppShell); the original `POO-5..46` batch was archived (Manager Console `POO-39..46` pending recreation). These files remain as the source specs / reference.

Original plan was 1 (BOOTSTRAP) + 13 (FOUNDATION) + 15 (DS) + 5 (Mocks/i18n) = 34. BOOTSTRAP (the `figma-inventory` trigger) was **superseded** because the inventory was produced directly (`IDS_REGISTRY.md` / `FIGMA_INVENTORY.md`), so 33 Foundation issues were created. Feature issues come from `IDS_REGISTRY.md` on demand.
